# Keybindings Cheatsheet — Every App on This Machine

One page per tool, the way the keys actually fire on **Rocky Linux 10 / GNOME 49
Wayland**. The companion PDF (`assets/keybindings-cheatsheet.pdf`) is built from
this same file.

**Legend** — `C` = Ctrl · `S` = Shift · `A` = Alt · `Super` = Windows key ·
`C+S` = Ctrl+Shift · `LEADER` = WezTerm leader (`Ctrl+A`, 1 s window) ·
`→ key` = press, release, then the next key (modal / prefix).

**Source of truth** — each table is extracted from the live config it names. Where
two scripts disagree, the divergence is flagged in [§ Conflict & precedence logic](#conflict--precedence-logic).

## Conflict & precedence logic

How overlapping keys are meant to resolve on this host.

### `Ctrl + A` — three layers, intentional chain
WezTerm leader → Zellij prefix → tmux prefix all use `Ctrl+A`. WezTerm's leader
captures it first; `LEADER → Ctrl+A` (and tmux's `Ctrl+A Ctrl+A`) forward a real
`Ctrl+A` inward. So nesting WezTerm › Zellij still works: tap twice to reach the
inner multiplexer. **No fix needed — this is by design.**

### `Super + ←/→/↑/↓` — three claimants, must pick one
PaperWM (focus/scroll columns), Tiling Assistant (snap halves), and GNOME native
(maximize/minimize on Up/Down) all want the Super+arrows. With PaperWM enabled it
grabs them first and the snap behaviour is lost.
**Logic:** run **one** tiler. Keep PaperWM for scrollable tiling, OR disable
PaperWM and let Tiling Assistant own snapping:

```bash
gnome-extensions disable paperwm@paperwm.github.com      # → Tiling Assistant snapping
# or keep PaperWM and disable the snap conflicter:
gnome-extensions disable tiling-assistant@leleat-on-github
```

### `Ctrl + Space` — resolved
Previously contested between zsh `autosuggest-accept` and an old rofi binding.
Rofi now lives on `Super+Space` (`setup-rofi-keybind.sh`), so `Ctrl+Space` is free
for the shell. If you still see the launcher fire, an old `gnome-launcher` scheme
is active — re-run `setup-rofi-keybind.sh` or use `→`/`End` to accept suggestions.

### `Super + Return` — two meanings
PaperWM = new window in column. WezTerm (when focused) = toggle fullscreen. No real
clash: PaperWM is a shell-global binding, WezTerm's is app-local and only matters
while WezTerm has focus and PaperWM isn't intercepting. If PaperWM eats it, rebind
WezTerm's fullscreen to `F11` (already bound).

### Terminal launch — `Super+T` vs `Super+Return`
Current scripts bind `Super+T` → ptyxis. The legacy doc lists `Super+Return` →
WezTerm. They come from different launcher scripts; only the one you ran is live.
Standardize on `Super+T` (current) and drop the legacy launcher to avoid surprise.

## Memorize order (frequency tiers)

**Tier 1 — every session:** `Super+Space` launcher · `C+S+D/E` split ·
`C+S+H/J/K/L` panes · `C+S+T/W` tab · `C+S+C/V` copy/paste.

**Tier 2 — many times a day:** `Ctrl+Tab` / `C+S+Tab` tab cycle · `Alt+1..9` jump ·
`C+S+Enter` zoom · `C+S+X` close pane · `Super+[`/`]` workspace.

**Tier 3 — weekly:** `C+S+P` profiles · `C+S+Z` Zellij · `C+S+F` search ·
`C+S+A+H/J/K/L` resize · `Ctrl + +/-/0` font · `Space e` nvim explorer.

**Tier 4 — occasional:** `C+S+A+P` palette · `LEADER y` copy last output ·
`LEADER r` resize mode · `F11` fullscreen · `Super+Q` close window.
