# Dotfiles Documentation

The single source of truth for **what is installed on this machine, how it is
configured, how to use it, and why each choice was made**. Everything here is
authored as plain `.mdx` (markdown-compatible — no JSX), so it renders in
GitHub, your editor, or any future docs site without changes.

> **Machine profile:** Rocky Linux 10.1 · GNOME 47 · Wayland (XWayland for a few
> apps — see [Known Quirks](#known-quirks)). Also drives a Dell/Arch laptop.
> Dotfiles are managed by **chezmoi**; runtimes by **mise**; theme is
> **Catppuccin Mocha** everywhere.

## Doc conventions

Each feature page follows the same template:

1. **Intro** — what it is, in one paragraph
2. **Why this (vs alternatives)** — the rationale and trade-off
3. **Install / enable** — exact commands or chezmoi path
4. **Usage** — day-to-day
5. **Keybindings** — table (where relevant)
6. **Customization** — what to tweak and where
7. **Troubleshooting** — known gotchas
8. **Links** — repo config path, deep-dive guide, upstream

**Status legend** (in each page's frontmatter): `live` (installed + matches
repo) · `diverged` (live config differs from repo — reconcile) · `pending` (in
repo, not yet applied here) · `missing` (needs install/build).

This tree is the **canonical** entry point. Longer reference guides under

`FULL_TOOLS_INVENTORY.md`, `APPS_GUIDE.md`, `OPEN_SOURCE_TOOLS.md`,
`SCRIPT_EXPLAINED.md`) remain as **deep-dive references** and are linked from the
matching section. The repo-wide task tracker is [`ROADMAP.md`](../ROADMAP.md);
the per-machine parity checklist content now lives in the
[Feature Catalog](./feature-catalog.mdx).

## Known quirks

GNOME's Mutter compositor does not implement `wlr-layer-shell` and ships an
explicit-sync path that crashes some apps' native Wayland backends. **rofi** and
**wezterm** therefore run on **XWayland** (applied automatically by chezmoi).
Full detail in [`md files/KEYBOARD-SHORTCUTS.md`](../md%20files/KEYBOARD-SHORTCUTS.md#known-quirks--gnome-wayland-why-xwayland).
