# Installation Reference

**Intro.** A single snapshot of *how this machine is built from scratch*: every
setup script, its size, what it installs, how long it takes, and how the
chezmoi config layer is applied on top. Use this to replicate the box, audit
what runs, or estimate a fresh install.

> For the *model* behind this (the three provisioning layers + run order), see
> [Provisioning Architecture](./architecture.mdx).

> **Snapshot:** 2026-06-09 · Rocky Linux 10.1 (also drives a Dell/Arch laptop) ·
> setup payload **232 KB** across 20 scripts · installs ~45 tools/apps.
> Entry point: `bash setup/setup.sh` (auto-detects OS).

## Build flow at a glance

```
setup.sh  --detect OS-->  setup-rocky.sh  (or setup-arch.sh)
  1. rocky-dev-setup-custom.sh   base dev env (dnf groups, git, python, node…)
  2. install-wezterm.sh          terminal (Flatpak)
  3. install-modern-cli.sh       rg fd bat eza delta fzf
  4. install-automation-tools.sh direnv just pre-commit
  5. install-extras.sh           clipboard / emoji / calc launcher tools
  6. install-workflow-tools.sh   33 workflow + Tier-2 tools (OS-independent)
  7. install-productivity.sh     6 office / deep-work Flatpaks
  8. gnome-desktop-setup.sh      theme / fonts / keybindings
  9. validate-install.sh         health check + log (final step)
--- then, run by you ---
  chezmoi init --apply           dotfiles into $HOME
  mise install                   pinned runtimes
```

## Install methods (OS-independence)

`install-workflow-tools.sh` is the cross-distro layer. It picks the first method
that works, so the same script runs on Rocky, Arch, Debian, openSUSE, or macOS:

| Method | Used for | Needs |
|--------|----------|-------|
| System package manager | rg, fd, fzf, jq, btop, entr, … | `dnf`/`pacman`/`apt`/`zypper`/`brew` (auto-detected) |
| `cargo install` | atuin, yazi, xh, navi, watchexec, git-cliff, dust, … | Rust (via mise) |
| `uv tool install` | visidata, llm, ruff, pre-commit | uv (bootstrapped if absent) |
| `go install` | duf, glow, gum, mlr, croc, lazydocker, yq | Go (via mise) |
| `gh extension` | gh-dash | gh CLI |
| Vendor `curl \| sh` | ollama, duckdb (fallback) | network |
| Flatpak (Flathub) | all GUI apps | flatpak |

## Time estimate (fresh machine)

Wall-clock dominated by **cargo source builds** and **Flatpak downloads** — both
bandwidth/CPU dependent. Re-runs are near-instant (everything is idempotent).

| Phase | Est. time | Notes |
|-------|-----------|-------|
| Base dev env (dnf) | 3–8 min | Package downloads + groupinstall |
| Modern CLI + automation + extras | 2–5 min | Mostly packages |
| Workflow tools — cargo builds | 15–30 min | yazi/atuin/watchexec compile from source |
| Workflow tools — go/uv/gh | 2–5 min | Fast |
| ollama | 1–3 min | ~hundreds of MB + service |
| Productivity Flatpaks | 5–20 min | LibreOffice/ONLYOFFICE runtimes are large (~1–3 GB total) |
| GNOME + validation | 1–2 min | gsettings + checks |
| **Total (cold)** | **~30–60 min** | **Re-run: <2 min** |

## chezmoi setup detail

Dotfiles are **not** installed by the setup scripts — they are applied separately
by chezmoi, keeping *config* (chezmoi) cleanly separate from *software* (setup).
See [chezmoi automation doc](../automation/chezmoi.mdx) for daily usage.

| Aspect | Value |
|--------|-------|
| Source of truth | `~/coding/Dotfiles` |
| Source root | `chezmoi/` (set by `.chezmoiroot` — scopes apply to this subdir only) |
| Naming | `dot_bashrc` → `~/.bashrc`; `private_` → mode 600; `executable_` → +x; `run_onchange_` → re-run on change |
| Tracked tops | `dot_bashrc`, `dot_zshrc`, `dot_gitconfig`, `dot_tmux.conf`, `dot_wezterm.lua`, `private_dot_config/`, `private_dot_local/bin/` |
| Configs under `~/.config` | mise, nvim, starship, zellij, lazygit, rofi, wofi, autostart, remote-desktop |
| Run-scripts | `.chezmoiscripts/run_onchange_after_gnome-launcher.sh` |
| Apply command | `sh -c "$(curl -fsLS get.chezmoi.io)" -- init --apply SathishKumarAI/Dotfiles` |

**Why the split:** software install is destructive/sudo-heavy and OS-specific;
dotfile apply is idempotent, per-user, and machine-aware via chezmoi templating.
Keeping them separate means you can re-apply configs without reinstalling, and
reinstall software without clobbering local config edits.

## Replicate this machine (future use)

```bash
# 1. Software (per-OS, auto-detected, ends with a validation report)
gh repo clone SathishKumarAI/Dotfiles ~/coding/Dotfiles
bash ~/coding/Dotfiles/setup/setup.sh

# 2. Dotfiles into $HOME
sh -c "$(curl -fsLS get.chezmoi.io)" -- init --apply SathishKumarAI/Dotfiles

# 3. Pinned runtimes
mise install

# 4. Confirm everything landed
bash ~/coding/Dotfiles/setup/validate-install.sh        # add --fix to heal gaps
```
